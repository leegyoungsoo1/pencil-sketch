# 웅토끼 영상의 Three.js 적용 검토

검토일: 2026-10-01

## 결론

현재 웅토끼를 곧바로 완전한 3D 캐릭터로 교체하지 않는다. 승인된 웅토끼 스프라이트의 얼굴과 그림체를 유지하면서, 배경·소품·카메라에 깊이를 주는 **2.5D 무대**로 Three.js를 적용하는 것이 가장 적합하다.

Three.js는 움직임을 스스로 만들어 주는 AI가 아니다. 걷기·뛰기·건행 같은 동작 원화는 계속 필요하다. 대신 그 원화를 3차원 공간의 평면에 놓고, 카메라 이동·앞뒤 가림·조명·그림자·입자 효과를 안정적으로 표현할 수 있다.

## 지금 방식과 달라지는 점

| 항목 | 현재 Canvas 2D | Three.js 2.5D 적용 |
|---|---|---|
| 웅토끼 | 투명 PNG 프레임 | 같은 PNG를 평면 텍스처로 사용 |
| 배경 | 한 장 이미지 | 하늘·건물·바닥·앞쪽 소품을 깊이별로 분리 |
| 이동 | 화면 좌표 이동 | 공간 안에서 이동하며 소품 앞뒤를 자연스럽게 통과 |
| 카메라 | 확대·이동 계산 | Dolly, pan, parallax와 초점 이동 |
| 조명·효과 | 직접 그린 효과 | 부드러운 그림자, 조명, 빛가루·종이·꽃가루 입자 |
| 자막 | Canvas 2D | 선명도를 위해 기존 2D 합성 유지 |
| MP4 | WebCodecs | 현재 고정 프레임 인코더를 그대로 사용 가능 |

## 가장 효과적인 장면

1. 공연장 입구에서 웅토끼가 팬을 맞고 실내 휴게 공간으로 안내하는 장면
2. 좌석 사이를 걸으며 3면 스크린을 확인하는 장면
3. 우체국·사진 공간에서 소품을 들고 앞뒤로 이동하는 장면
4. 카메라가 팬 뒤에서 웅토끼 쪽으로 천천히 다가가는 도입
5. 건행 인사 때 조명과 종이 꽃가루가 공간 안에서 퍼지는 결말

이 방식은 지금의 평면적인 느낌을 크게 줄이면서 승인된 캐릭터 얼굴을 바꾸지 않는다. 장면마다 전신을 새로 그리지 않아도 같은 걷기 프레임을 방향·크기·카메라 거리와 조합해 다양하게 보일 수 있다.

## 구현 구조

```text
스토리 JSON
  └─ 시간표·대사·카메라·캐릭터 동작
       └─ Three.js 오프스크린 렌더러
            ├─ 깊이별 배경 평면
            ├─ 웅토끼 스프라이트 프레임
            ├─ 의자·표지판·우체통·스크린 소품
            ├─ 조명·그림자·입자
            └─ 카메라
                  ↓
       기존 2D 출력 캔버스에 합성
            ├─ 큰 한글 자막
            ├─ 출처·연도·장소
            └─ WebCodecs MP4 프레임
```

미리보기와 저장 결과가 다르지 않도록 `requestAnimationFrame`의 실제 시간 대신 프레임 번호로 장면 시간을 계산한다. 예를 들어 30fps의 150번째 프레임은 언제 저장해도 정확히 5초 장면이다.

Three.js 화면을 별도 WebGL 캔버스에 그리고, 현재의 2D 출력 캔버스가 이를 복사한 뒤 자막을 올린다. 이 구조는 한글 자막의 선명도를 유지하고 현재 WebCodecs 저장 코드를 크게 바꾸지 않는다. 표지판이나 공연장 화면처럼 공간에 붙어 있어야 하는 글자만 `CanvasTexture`로 만든다.

## 1차 시험 범위

새 영상 전체를 만들기 전에 12~15초짜리 기술 시험 하나만 만든다.

- 장면: 고양 공연장 바깥 → 실내 휴게 공간
- 캐릭터: 현재 승인된 웅토끼의 건행, 걷기, 안내 포즈
- 공간: 배경 4층(하늘·건물·바닥·전경 의자), 간단한 표지판과 문
- 카메라: 천천히 앞으로 이동하고 웅토끼를 따라 좌우 이동
- 효과: 바닥 접촉 그림자, 문이 열릴 때 부드러운 냉기 입자
- 검증: PC·모바일 미리보기, 1080p 30fps MP4 15초, 기존 Canvas 2D 대체 화면과 성능 비교

시험이 승인되면 같은 무대를 12개 클립에 재사용한다. 승인되지 않으면 기존 Canvas 2D 제작기로 즉시 돌아갈 수 있게 별도 페이지와 모듈로 만든다.

## 완전 3D 캐릭터를 미루는 이유

완전한 3D 웅토끼는 GLB 모델, 뼈대, 피부 가중치, 얼굴 표정용 모프 타깃, 걷기·뛰기·건행 애니메이션이 모두 필요하다. 카메라 각도를 자유롭게 바꿀 수 있다는 장점은 크지만, 현재 승인된 임영웅 닮은 얼굴이 다른 각도에서 달라지거나 어색해질 위험이 크다. 여러 편의 2.5D 영상이 실제로 성과를 낸 뒤 장기 자산으로 제작하는 편이 합리적이다.

## 모바일과 저장 시 주의점

- 시작할 때 WebGL2 지원 여부를 검사하고 지원하지 않으면 기존 Canvas 2D로 자동 전환한다.
- 모바일에서는 기기 픽셀 비율을 그대로 사용하지 않고 상한을 둔다. 높은 픽셀 비율은 렌더링 비용을 크게 늘릴 수 있다.
- 그림자는 주요 캐릭터와 큰 소품에만 적용하고, 멀리 있는 배경은 조명을 미리 그린 이미지로 사용한다.
- 모든 텍스처를 미리 불러온 뒤 녹화를 시작한다. 녹화 중 네트워크 요청은 하지 않는다.
- Three.js 버전을 저장소에 고정하거나 정확한 버전의 모듈을 묶어, 배포 뒤 라이브러리 변경으로 영상이 달라지지 않게 한다.
- 페이지를 초기화하거나 다른 작품을 열 때 텍스처·재질·렌더러의 GPU 자원을 해제한다.
- Three.js는 음향 생성과 MP4 음성 합성을 대신하지 않는다. 음악·효과음은 Web Audio 또는 후반 편집 흐름을 유지한다.

## 공식 문서 근거

- HTML Canvas를 텍스처로 사용하는 `CanvasTexture`: https://threejs.org/docs/pages/CanvasTexture.html
- 애니메이션 재생과 시간 제어를 담당하는 `AnimationMixer`: https://threejs.org/docs/pages/AnimationMixer.html
- GLB/glTF 모델·뼈대·애니메이션 로딩: https://threejs.org/manual/pages/loading-3d-models.html
- 애니메이션 클립·뼈·모프 타깃·크로스페이드: https://threejs.org/manual/pages/animation-system.html
- 렌더러, 애니메이션 루프와 GPU 자원: https://threejs.org/docs/pages/WebGLRenderer.html
- 화면 크기와 기기 픽셀 비율 성능 고려: https://threejs.org/manual/pages/responsive.html
- WebGL2 지원 검사: https://threejs.org/docs/pages/WebGL.html

## 도입 결정

**도입 추천:** 2.5D 시험 장면부터 적용.

**당장 도입하지 않음:** 완전 3D 얼굴·몸 모델, 물리 엔진, 복잡한 게임 조작.

스토리 승인 후 첫 장면을 2.5D와 기존 2D 두 버전으로 비교하면, 화질·제작 시간·모바일 저장 안정성을 실제 결과로 판단할 수 있다.
